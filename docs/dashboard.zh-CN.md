# 使用指南

**简体中文** · [English](dashboard.en.md) · [文档目录](README.md)

## 连接设置

首次启动时，在引导页填写控制器地址和密钥。地址可使用局域网 IP、`.local` / `.lan` 域名或局域网主机名，例如 `192.168.1.1:9090`。密钥应与控制器的 `secret` 一致；“检查连接”用于验证 API 是否可访问。

使用 OpenClash 或 Nikki 的配置管理、快捷设置和重启功能时，还需填写 SSH 密码。账号为 `root`，端口默认 `22`，可按设备配置修改。首次 SSH 连接会显示主机指纹，请核对后确认。

点击“下一步”后，应用识别代理软件和内核，并在偏好页预选软件。无法识别时使用“Mihomo 通用配置”；可手动修改，也可先保存、稍后连接。高级选项中的“代理软件”可随时调整，离线时也能保存。

应用在冷启动、从后台返回和保存连接设置后重新识别。无法确认软件时保留已确认的选择；需要手动确认时，选择面板只在控制器已连接的首页出现，连接失败不会触发。

## 首页

默认顺序为运行状态、流量信息、运行概览、当前配置、运行操作和快捷设置。运行状态显示软件、内核版本和连接状态；流量及概览展示用量、速率和连接数。

在列表底部打开“自定义首页”，长按拖动排序，用开关显示或隐藏卡片，修改自动保存在本机。“恢复默认”重置顺序和可见性；隐藏全部卡片后仍可进入自定义。

不同代理软件共用布局偏好。不支持的卡片和选项在首页及自定义中隐藏，重新可用后恢复原位置；从未排序的新卡片追加在已排序卡片之后。手动隐藏的卡片不会因切换软件而重新显示。

## 适配范围

| 功能 | OpenClash | Nikki | Mihomo 通用配置 |
| --- | --- | --- | --- |
| 状态、流量、代理与规则、连接操作 | 支持 | 支持 | 按控制器 API 能力提供 |
| 代理模式 | 支持 | 支持 | 支持 |
| DNS 模式、流量接管、区域绕过、嗅探、DNS 遵循规则 | 支持 | 支持，见下方限制 | 不提供专用设置 |
| 流媒体自动选择 | 设备支持时可用 | 不支持 | 不支持 |
| YAML 管理、服务重启 | 支持 | 支持，订阅缓存只读 | 不支持 |

其他尚未专门适配的软件使用 Mihomo 通用配置。软件名称与内核名称分别显示；运行 Mihomo 内核不代表管理软件就是 OpenClash。

### Nikki

- TCP/UDP 接管使用 Redirect、TPROXY、TUN 的组合预设。
- 区域绕过的“大陆”同时开启大陆 IPv4 和 IPv6 绕过，“停用”同时关闭。如果两者当前值不同，选择任意一项会将其统一。
- 核心独立模式隐藏快捷设置；使用混入文件覆盖时，仅保留区域绕过。
- 本地配置目录为 `/etc/nikki/profiles`。订阅缓存 `/etc/nikki/subscriptions` 只读；需要修改时上传为本地配置后再激活。运行生成的 `/etc/nikki/run/config.yaml` 不作为编辑对象。

适配不包含 Nikki 的全部 LuCI 选项。快捷设置中的可用项以当前设备配置为准。

## YAML 管理

“当前配置”卡片显示正在使用的配置。切换配置需选择文件并确认，应用随后保存引用、重启代理服务并验证结果。重启可能中断现有连接。

“编辑配置”打开编辑器。顶部文件名用于选择编辑对象，不会直接切换运行配置；右上角文件菜单提供上传、重命名、导出和删除。

| 操作 | 注意事项 |
| --- | --- |
| 保存 | 写回当前文件；退出时若改动了正在运行的配置，可选择重启服务 |
| 上传 | 同名文件需确认覆盖；上传其他文件不会自动激活 |
| 导出 | 包含当前未保存的编辑内容，不写回路由器 |
| 重命名 | 保留当前编辑内容；正在使用的订阅文件需先切换配置 |
| 删除 | 需确认；正在使用的配置不能删除，无法确认运行配置时也不能删除或重命名 |
| 切换编辑文件 | 未保存内容可选择保存、放弃或取消 |

仅处理受支持目录内的 `.yaml` / `.yml` 文件，单文件最大 `5 MiB`。OpenClash 支持 `/etc/openclash/config`、`/openclash/config`、`/etc/clash/config` 和 `/root/.config/clash/config`，上传目录为 `/etc/openclash/config`。读取失败的文件不能保存。

### SFTP 不可用

文件列表通过 SSH 获取，读写使用 SFTP。能列出文件但无法打开时，按编辑器提示检测 SFTP。确认 OpenWrt 缺少组件后，可查看并确认安装命令，由应用通过 `opkg` 或 `apk` 安装 `openssh-sftp-server`；需要 root 权限。

安装超时或断线后先点“重新检测”，确认结果后再决定是否重试。已有组件但握手失败时，应检查 SSH 的 SFTP 配置；网络或认证错误不代表缺少组件。

## 刷新与故障处理

页面可见且应用在前台时，首页自动刷新。运行数据约每秒更新，订阅约每 30 秒更新，配置和快捷设置正常时约每 15 秒同步；手动刷新和恢复连接后立即读取。切换标签或进入后台会暂停对应轮询。

| 现象 | 处理 |
| --- | --- |
| 无法连接 | 检查设备网络、控制器地址、端口和 `external-controller`；iOS 还需确认局域网权限 |
| 认证失败 | 检查控制器密钥；SSH 失败时另行核对密码、端口和主机指纹 |
| Web 面板加载失败 | 点击重试；前台可见的离线页面会自动检测恢复，认证错误需要先修正配置 |
| 设置已保存但重启失败 | 使用重启入口重试；已确认保存的设置无需重复写入 |
| 操作结果未确认 | 先检查路由器实际状态并刷新，再决定是否重试，避免重复操作 |

面板布局、导入和更新见 [Zashboard 指南](bundled-zashboard.md)。
